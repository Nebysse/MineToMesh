# MC glTF Exporter 0.2.0 通用渲染兼容与 OBJ 导出设计

## 1. 背景

0.1.0 在 Minecraft 1.21.1、NeoForge 21.1.244 的真实模组环境中完成初步导出验证后，暴露出三类边界：

1. 使用 Flywheel GPU 实例化的机械动力方块实体在捕获时输出 0 顶点，因而被替换为洋红占位符。
2. 车万女仆模型几何与 UV 完整，但运行时皮肤不在标准资源管理器路径中，纹理读取失败。
3. glTF 2.0 只能保存点、线和三角拓扑，无法让 Blender 导入结果直接保留 Minecraft 原始四边面。

真实验证报告来自包含 Create 6.0.10、Flywheel 1.0.6、Touhou Little Maid 1.5.3 的客户端实例。报告记录了 17 个 `BLOCK_ENTITY_ZERO_VERTICES`，涉及 `FluidTankRenderer`、`GearboxRenderer` 和 `BracketedKineticBlockEntityRenderer`；同时记录了运行时方块图集与女仆皮肤的 `TEXTURE_READ_FAILED`。

0.2.0 的目标是在保持客户端侧、选区式、Blender 可编辑导出的前提下，建立面向渲染后端的通用兼容层，并在每次导出时同步生成 glTF 与 OBJ。

## 2. 设计目标

### 2.1 必须实现

- 模组版本升级为 `0.2.0`。
- 保持 Minecraft 1.21.1 与 NeoForge 21.1.244 最低兼容基线。
- 每次 `/mcgltf export <名称> [confirm]` 同时生成 glTF 与 OBJ。
- glTF 保持标准三角拓扑并继续通过校验。
- OBJ 精确保留捕获源中的原始 `QUADS`，其他拓扑安全转换为三角面。
- 普通方块在 OBJ 中按区段与材质分组；方块实体、实体和占位符保持独立对象。
- 将静态方块模型与附加方块实体渲染视为同一世界对象的两个可组合部分。
- 静态主体成功而附加 Renderer 输出 0 顶点时，不生成占位符。
- 建立渲染后端级兼容作用域，首版支持 Flywheel 1.x，不按 Create 方块或 Renderer 类型写特判。
- 纹理读取依次覆盖资源文件、CPU 动态纹理和已加载 GPU 纹理。
- 捕获与回读失败时恢复所有后端与 OpenGL 状态，并记录稳定诊断。
- 兼容与完整性优先于导出期间的实时帧率。

### 2.2 明确不做

- 不在 0.2.0 中实现完整 OpenGL Draw Call 截取器。
- 不逐个解析 Create、Touhou Little Maid 或其他模组的私有模型格式。
- 不把 Create 或女仆模组设为运行时硬依赖。
- 不对原始三角面做猜测性的共面合并或 N-gon 重建。
- 不承诺还原完全由着色器生成且没有 CPU 备用几何的对象。
- 不改变原有坐标、选区、未加载区块、取消、软限制和输出目录策略。

## 3. 根因分析

### 3.1 Flywheel 零顶点

Flywheel 提供替代 Minecraft 方块实体和实体渲染的 GPU 实例化路径。Create 的多个 Renderer 在 `VisualizationManager.supportsVisualization(level)` 为真时提前返回，几何由 Flywheel 的实例数据和自定义着色器提交，当前 `CapturingMultiBufferSource` 因而看不到任何顶点。

这些 Renderer 同时保留了非 Flywheel 的 `VertexConsumer` 备用路径。捕获期间暂时让后端报告为关闭，再调用游戏已经注册的 Renderer，可以获得当前对象的 CPU 几何，而无需解析 Create 的具体模型类。

### 3.2 储罐假重复

储罐静态外壳由 `BakedModel` 捕获。空储罐、非控制器储罐或没有附加可见内容的储罐 Renderer 可以合法输出 0 顶点。0.1.0 将任何方块实体零输出直接判为失败并生成占位符，造成“主体外再重复一份”的视觉结果。

占位决策必须综合静态模型与附加 Renderer 两条路径，不能由 `BlockEntityCapture` 单独决定。

### 3.3 运行时纹理缺失

0.1.0 仅对 `DynamicTexture` 读取 CPU 像素；其他 `AbstractTexture` 一律回到 `ResourceManager` 查找 PNG。方块图集和外部模型包皮肤可能已经上传到 GPU，却没有对应的资源管理器文件，因此模型与 UV 正常而图像降级为棋盘格。

纹理链的最后一个通用数据源应为当前 OpenGL 纹理对象，而非具体模组的文件目录。

### 3.4 glTF 面拓扑限制

glTF 2.0 的核心 primitive mode 仅包含点、线、三角形、三角条带和三角扇，不包含 Quad 或 N-gon。OBJ 的 `f` 可以表达四个及更多顶点，因此 0.2.0 使用双格式输出满足传输兼容与 Blender 多边形编辑两个目标。

## 4. 总体架构

### 4.1 `ObjectCaptureOrchestrator`

该组件统一负责一个世界对象的捕获结果组合：

1. 捕获静态 `BakedModel`。
2. 捕获流体几何。
3. 在兼容作用域中捕获方块实体附加 Renderer。
4. 合并三条路径的几何、计数器和诊断。
5. 根据完整结果决定成功、部分成功、合法空附加渲染或占位。

方块实体捕获层只报告几何与执行结果，不再自行生成占位符。实体没有静态方块主体，仍由统一结果策略在全部捕获路径失败时生成实体包围盒占位。

### 4.2 `RenderFallbackRegistry`

核心定义后端无关的作用域接口：

```text
检测当前运行环境
→ 保存后端状态
→ 进入备用渲染作用域
→ 调用已注册 Renderer
→ finally 恢复后端状态
```

注册表按优先级选择可用适配器。没有适配器时使用空作用域，保持现有标准捕获路径。

### 4.3 Flywheel 1.x 适配器

Flywheel 适配器只识别 Flywheel 后端 API 和状态，不读取 Create 注册表、方块 ID、PartialModel 或 Renderer 类。它采用运行时类检测，未安装 Flywheel 时不加载相关实现。

适配器要求：

- 保存当前 backend 对象。
- 在当前 Renderer 调用期间切换为 Flywheel 的 off backend，使 `supportsVisualization` 返回假。
- 支持嵌套作用域，最外层退出时才恢复。
- 在任何异常路径通过 `finally` 恢复原 backend。
- 仅在客户端渲染线程运行。
- 不重置、销毁或重建当前世界的 Flywheel VisualizationManager。

该适配层是渲染后端兼容模块。所有使用 Flywheel 且保留备用 Renderer 的模组都自动受益。

### 4.4 `TextureAcquisitionChain`

纹理链由独立 Provider 组成：

1. `ResourceTextureProvider`：读取资源包原始 PNG。
2. `DynamicTextureProvider`：读取 CPU `NativeImage`。
3. `GpuTextureReadbackProvider`：从已加载 OpenGL texture level 0 回读 RGBA8。
4. `MissingTextureProvider`：生成稳定棋盘格并记录失败。

Provider 返回统一的 `TextureImage`、来源类型和诊断。每次导出建立独立缓存，以资源 ID、GL ID、尺寸和内容哈希去重；资源重载后不跨导出复用旧 GPU ID。

### 4.5 双拓扑场景层

当前 `PrimitiveAccumulator` 在封口时立即将所有源拓扑转换为 glTF 索引。0.2.0 在中间层保留：

- 原始 `PrimitiveMode`
- 原始顺序顶点流
- 材质引用
- 对象与分组信息

后台 Writer 分别执行：

- glTF：按现有规则转换为 glTF 合法拓扑。
- OBJ：Quad 每四个顶点生成一个四边面；Triangles 每三个顶点生成一个三角面；Strip 与 Fan 安全展开为三角面。

中间层不跨原始图元、材质或 UV 接缝合并面。

## 5. 数据流

```text
客户端世界对象
  → ObjectCaptureOrchestrator
  → BakedModel / Fluid / Renderer replay
  → SourcePrimitive + ObjectCaptureOutcome
  → 容量为 2 的后台写入队列
      → Streaming glTF Writer
      → Streaming OBJ/MTL Writer
  → 共享 TextureRegistry
  → Report Writer
  → OutputTransaction commit
```

每个对象只捕获一次。glTF 与 OBJ 消费同一份 `SourcePrimitive`，确保姿态、材质、UV 与诊断一致。Writer 在线程安全边界外只处理不可变场景值，不访问客户端世界或 OpenGL。

GPU 回读和 Renderer 重放发生在客户端渲染线程。用户已确认导出完整性优先，因此这些步骤允许偶发超过原有 6ms Tick 预算；后台文件写入仍使用容量为 2 的有界队列。

## 6. 对象结果与占位规则

| 静态模型 | 附加渲染 | 最终结果 |
|---|---|---|
| 有几何 | 有几何 | 两部分同时导出 |
| 有几何 | 0 顶点 | 仅导出静态主体，不生成占位符 |
| 无几何 | 有几何 | 导出附加渲染结果 |
| 无几何 | 0 顶点 | 生成占位符并记录失败 |
| 一路异常，另一路成功 | 保留成功部分并记录部分降级 |
| 全部路径异常 | 生成占位符与完整失败诊断 |

合法零输出与失败必须区分：Renderer 正常返回但没有顶点属于 empty；Renderer 抛出异常、后端作用域失败或拓扑无效属于 failed。

## 7. GPU 纹理回读

### 7.1 执行步骤

1. 从 `TextureManager` 获取当前 `AbstractTexture` 与 GL ID。
2. 验证纹理对象存在并绑定了二维基础 mip 层。
3. 查询 level 0 宽高与可读格式。
4. 保存当前 active texture、2D texture binding、pack alignment 和相关像素传输状态。
5. 回读 RGBA8 像素。
6. 恢复所有保存的 GL 状态。
7. 校验尺寸与字节长度，按内容哈希去重。
8. 生成 PNG 并注册到共享纹理表。

### 7.2 UV 规则

- 独立实体纹理保持 Renderer 提交的原始 UV。
- 整张运行时图集回读时保持图集 UV，不执行 sprite 局部归一化。
- `BakedQuad` 的 atlas sprite 仍优先走现有 sprite 提取路径，并归一化到导出的独立 sprite PNG。

### 7.3 失败处理

GPU 回读失败后生成棋盘格，记录纹理 ID、GL ID、尺寸、Provider、异常类型和错误信息。失败不得改变后续游戏渲染使用的纹理绑定。

## 8. OBJ 与 MTL 输出

### 8.1 文件布局

```text
mcgltf-exports/<名称>/
├─ <名称>.gltf
├─ <名称>.bin
├─ <名称>.obj
├─ <名称>.mtl
├─ report.json
├─ textures/
│  ├─ minecraft/
│  ├─ <modid>/
│  └─ generated/
└─ materials/
   └─ *.json
```

### 8.2 OBJ 分组

- 普通方块按区段建立 `o`，按材质建立 `g`。
- 方块实体每个实例建立独立 `o`。
- 普通实体每个实例建立独立 `o`。
- 占位符每个实例建立独立 `o`。
- 对象与组名称使用稳定、可预测的转义规则。

### 8.3 面与索引

- 输出 `v`、`vt`、`vn` 与 `f v/vt/vn`。
- 原始 Quad 输出四索引面。
- 原始 Triangle 输出三索引面。
- Strip 和 Fan 展开为 Triangle。
- 坐标使用 `(X,Y,Z) → (X,Y,-Z)`。
- 镜像坐标后同步调整绕序，使 glTF 与 OBJ 的正面和法线方向一致。
- OBJ 使用全局递增索引，Writer 流式维护偏移，不回写历史顶点。

### 8.4 MTL 映射

- 基础颜色纹理写入 `map_Kd`。
- 透明度使用 `d`，存在独立透明图时允许写入 `map_d`。
- 发光颜色尽量写入常见的 `Ke`。
- 标准 MTL 无法表达的双面、混合与 Minecraft 特有语义继续写入 `materials/*.json`。
- glTF 与 OBJ 共用同一批 PNG，不复制纹理。

## 9. 输出事务与取消

`.gltf`、`.bin`、`.obj`、`.mtl`、纹理、材质旁车与报告属于同一事务。正式目录只在全部核心 Writer 完成、内部校验通过且报告写入成功后提交。

取消或失败时：

- 停止接受新批次。
- 让 Writer 完成当前不可中断写操作后退出。
- 关闭所有流。
- 恢复渲染后端与 GL 状态。
- 保留现有失败现场策略，不提交伪成功目录。

## 10. 诊断与报告

报告继续记录稳定对象 ID、世界位置、Renderer 类与异常类型。新增诊断码：

- `RENDER_BACKEND_FALLBACK_USED`
- `RENDER_BACKEND_FALLBACK_FAILED`
- `AUXILIARY_RENDERER_EMPTY`
- `GPU_TEXTURE_READBACK_USED`
- `GPU_TEXTURE_READBACK_FAILED`
- `PARTIAL_OBJECT_CAPTURE`
- `OBJECT_CAPTURE_FAILED`

0.2.0 报告应能区分：标准捕获成功、后端备用路径成功、GPU 纹理回读成功、合法空附加渲染、部分对象降级和最终占位。

## 11. 测试设计

### 11.1 单元测试

- 对象结果判定矩阵的全部分支。
- 静态主体成功、附加渲染为空时占位符计数为 0。
- 后端作用域正常、异常、嵌套与未安装状态下的恢复行为。
- 同一 Quad 在 glTF 中生成两个三角面，在 OBJ 中生成一个四边面。
- Strip 与 Fan 的安全展开。
- 坐标镜像后的绕序和法线一致性。
- OBJ 全局顶点、UV、法线索引与分组。
- MTL 材质、透明度和纹理相对路径。
- 纹理 Provider 优先级、缓存、内容去重与失败降级。
- GPU 回读成功和异常时的 GL 状态恢复。
- 双 Writer 任一路径失败时输出事务不提交。

### 11.2 开发测试模组夹具

增加：

- 静态模型成功、附加 Renderer 合法输出 0 顶点的方块实体。
- 模拟加速后端启用时零输出、进入备用作用域后输出 Quad 的 Renderer。
- 只有 GPU 纹理、资源管理器中不存在 PNG 的实体。
- 完全 GPU-only 且没有备用路径的对象。

夹具验证通用接口，不依赖 Create 或女仆模组。

### 11.3 真实模组验收

环境：

- Minecraft 1.21.1
- NeoForge 21.1.244
- Create 6.0.10
- Flywheel 1.0.6

验收标准：

- 齿轮箱转轴与动力部件按捕获时姿态导出。
- 有液体的储罐保留实际液位。
- 空储罐与非控制器储罐不生成错误占位符。

- 生产 JAR 不包含开发测试模组。

## 12. 兼容性声明

0.2.0 的通用兼容范围为：

- 标准 `BakedModel`。
- 通过 `VertexConsumer` 输出的方块实体与实体 Renderer。
- 使用已支持加速后端且保留 CPU 备用 Renderer 的模组。
- 已经加载到 OpenGL 且可回读的二维纹理。

完全由着色器生成、没有 CPU 备用几何，或使用未知私有 GPU 管线的对象仍可能降级为占位符。此边界必须在 README 和报告中明确，不使用“所有模组绝对兼容”的表述。
