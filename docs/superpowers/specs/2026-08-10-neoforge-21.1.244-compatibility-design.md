# NeoForge 21.1.244 兼容性设计

## 目标

将 MC glTF Exporter 的 Minecraft 1.21.1 NeoForge 最低兼容版本从 `21.1.248` 下调至 `21.1.244`，并以 `21.1.244` 作为实际编译与自动化验证基线，而非仅放宽模组元数据。

兼容口径：支持 Minecraft 1.21.1、NeoForge `21.1.244` 及后续兼容的 `21.1.x` 版本。

## 变更范围

1. 将 `gradle.properties` 中的 `neo_version` 改为 `21.1.244`。ModDevGradle 将据此解析 244、编译生产代码、测试代码和开发测试模组。
2. 生产模组的 `neoforge.mods.toml` 继续通过 `${neo_version}` 生成最低版本范围，因此自动变为 `[21.1.244,)`。
3. 将开发测试模组的 NeoForge 依赖范围同步改为 `[21.1.244,)`，确保测试夹具不会人为抬高运行门槛。
4. 更新 README、原始规格及实施计划中的版本描述，避免文档继续宣称最低要求为 248。
5. 将 glTF 根 extras 中的 NeoForge 版本由硬编码值改为从当前运行时模组列表读取。导出结果记录真实运行版本，在 244、248 或更新版本运行时均不会产生错误元数据。

## 不变项

- Minecraft 版本保持 `1.21.1`。
- Java、Gradle、ModDevGradle、模组版本及 glTF 输出契约不变。
- 不维护两个独立源码分支，也不加入版本条件反射；源码必须直接通过 244 的编译 API。
- 生产 JAR 仍不得包含 `mcgltf_test` 开发夹具。

## 验证

1. 执行 `./gradlew.bat clean test build`，确认全部生产代码、单元测试和开发测试模组均使用 NeoForge 21.1.244 成功编译。
2. 检查 `build/libs/mcgltf-0.1.0.jar`，确认生产 JAR 不含 `mcgltf_test`。
3. 检查生成的 `META-INF/neoforge.mods.toml`，确认最低 NeoForge 范围为 `[21.1.244,)`。
4. 执行 `./gradlew.bat runClient` 启动开发客户端，确认模组与测试夹具在 244 环境完成初始化和资源加载，无致命错误。
5. 保留现有导出与生命周期测试，确保兼容性下调没有改变功能行为。

## 失败处理

若代码无法在 244 编译，优先定位 244 至 248 之间发生变化的 API，并改用 244 已存在且在后续 21.1.x 保持兼容的调用方式。不得退回“使用 248 编译、仅放宽元数据”的伪兼容方案。
