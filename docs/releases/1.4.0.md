# MineToMesh 1.4.0

滚动导出热修复与可用性版本。NeoForge `1.4.0` 与 Fabric `1.4.0-fabric-alpha.1` 同步升级。

## 修复

- **会话协议顺序**：`ExportSessionAccepted` 现在先于任何批次载荷到达客户端，滚动导出不再卡在“等待服务端会话”。
- **批次可读性等待**：客户端收到 `BatchReady` 后按 tick 轮询区块可读性，全部到达才回执并开始捕获；25 秒未到齐才判失败。不再因为数据包时序误判“不可读”而瞬间失败。
- **会话拒绝可被接收**：等待授权阶段的拒绝包不再被静默丢弃，第二次导出不再永久卡住。
- **完成握手**：客户端在所有批次捕获并写入完成后发送 `ExportClientCompleted`，服务端不再 120 秒最终化超时。
- **进度遥测**：`totalPositions` 按真实捕获单元计算；写入区间在捕获完成前不再把进度钉到 80%，批次持久化按单元计数；进度条从 0 连续爬升到 100。
- **大 UI 缩放拉伸**：九宫格边框不再随 GUI 缩放比压缩，界面在任何 UI 尺寸下保持一致的边框与按钮比例。

## 新能力

- **合并网格开关**：GUI 新增“合并网格”，随魔杖持久化。开启后整片区块几何在 glTF 与 USDA 中合并为单一对象 `selection/chunks_merged`（多材质各成一个 primitive）；关闭时保持按区块 section 分对象。旧魔杖默认关闭。
- **GUI 参数控件**：右侧面板可直接修改每批区块数（1～16，随魔杖保存）与处理线程数（按 CPU 上限钳制，随本机保存至 `config/minetomesh/client-export-settings.json`）；支持滚轮步进与回车提交，会话进行中锁定。
- 捕获改为会话级滚动累积：所有批次的几何追加进同一个导出任务，按批次确认服务端后释放票据。

## 行为变化

- 导出 GUI 高度从 216 增加到 238 以容纳新控件。
- 进行中导出的 Raw Worker 并行管线仍未启用，捕获在主线程按 6 ms 预算推进。

## 构建与验证

```powershell
./gradlew.bat :neoforge-1.21.1:test :neoforge-1.21.1:build --no-configuration-cache
./gradlew.bat :fabric-26.2:test :fabric-26.2:build --no-configuration-cache
```

双平台全套测试、构建与专用服务器冒烟通过；真实客户端、Blender 导入与 Khronos Validator 验收见 `docs/testing/1.3.0-rolling-export-verification.md` 的人工矩阵。
