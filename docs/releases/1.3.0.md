# MineToMesh 1.3.0

超视距选区滚动导出。NeoForge `1.3.0` 与 Fabric `1.3.0-fabric-alpha.1` 同步升级。

## 新能力

- **超视距滚动强加载**：服务端按紧凑 `4×4` 宏窗口分批强制加载选区区块，临时切换发起玩家的区块追踪中心，使客户端可以捕获视距外内容。
- **全服随机刻冻结**：导出期间 `randomTickSpeed = 0`，正常结束、取消、失败、断线、超时与服务端重启后均恢复会话前数值。恢复日志位于 `config/minetomesh/export-session-recovery.json`。
- **服务端唯一导出会话**：全服同时只允许一个会话，所有确认都校验玩家、魔杖、维度与批次序号，重复包幂等，迟到包拒绝。
- **可配置 CPU 工作线程**：上限 `max(1, min(16, CPU逻辑线程数 - 2))`，默认最多 `4`。设置保存在客户端本机 `config/minetomesh/client-export-settings.json`，损坏文件自动隔离并回退默认值。
- **每批区块数随魔杖持久化**：`1～16`，默认 `4`，旧魔杖自动回退 `4`。
- **可中途停止**：点击“停止导出”不关闭 GUI，等待服务端清理确认后可以再次导出。
- **完整生命周期进度**：加载、同步、捕获、处理、写入、校验与清理分段进度；输出发布、服务端恢复与追踪中心恢复全部完成后才显示 100%。

## 行为变化

- 导出期间玩家视角所在世界可能短暂卸载或闪烁，这是追踪中心切换的预期表现。
- 远方区块加载或同步失败时整个导出失败，不再发布带缺口的成功结果。
- 会话开始后批次大小与工作线程数锁定，GUI 修改只影响下一次导出。

## 已知边界

- 客户端渲染器捕获仍然按批次驱动；纯数据转换可并行，Minecraft 世界、渲染器、纹理与 GPU 访问保持在合法线程。
- 真实客户端、Blender 导入、Khronos Validator 与中文输入法的视觉验收无法自动化，执行状态见 `docs/testing/1.3.0-rolling-export-verification.md`。

## 构建

```powershell
./gradlew.bat :neoforge-1.21.1:test :neoforge-1.21.1:build --no-configuration-cache
./gradlew.bat :fabric-26.2:test :fabric-26.2:build --no-configuration-cache
```

产物：

- `neoforge-1.21.1/build/libs/MineToMesh-1.3.0-neoforge-1.21.1.jar`
- `fabric-26.2/build/libs/MineToMesh-1.3.0-fabric-alpha.1+mc26.2.jar`
