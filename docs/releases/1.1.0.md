# MineToMesh 1.1.0

MineToMesh 1.1.0 补全了 1.0.0 坐标手性修复遗漏的动态渲染路径，并降低 Create 等模组大量动态方块导入 Blender 后的对象碎片数量。

## 修改内容

### 修复动态模型镜像与法线反向

- 清除方块实体渲染、普通实体渲染及失败占位网格中残留的 `Z -> -Z` 轴反射。
- 移除 MineToMesh 注入到方块实体和普通实体 `PoseStack` 中行列式为 `-1` 的负缩放。
- Create 传送带、齿轮、传动杆、机械手等动态模型不再沿 Blender Y 轴镜像。
- 动态模型的顶点坐标、法线和三角形正面重新保持同一右手坐标契约。
- 方块实体及普通实体的 `extras.localPosition`、实体占位包围盒和方块占位包围盒统一保留正向局部 Z。

Blender 导入 glTF 后的映射保持：

- Minecraft `+X` → Blender `+X`
- Minecraft `+Y` → Blender `+Z`
- Minecraft `+Z` → Blender `-Y`

### 动态方块实体按材质全局合批

- glTF 与 OBJ 同步按完整 `MaterialKey` 合并动态方块实体几何。
- 相同材质键的连续传送带等动态部件导入 Blender 后形成一个网格对象，不再按每个方块位置拆分。
- 合批键包含纹理、透明模式、透明阈值、双面、发光、混合语义和采样模式；仅纹理名称相似不会误合并。
- glTF 为每个材质键建立一个全局 BlockEntities Mesh/Node。
- OBJ 使用按材质分离的临时片段流，在导出结束时写成一个对象，并在成功、取消或失败后清理临时文件。
- 静态区块、普通实体、占位网格和草侧 Overlay 继续保留原有对象边界。

### 元数据

- NeoForge 作者字段更新为 `岚苍穹 nebysse`。
- 保留 512×491 正式模组封面及 `logoBlur=true`。

## 坐标兼容说明

已经导出的旧文件不会被自动修改。若 Create 动态模型存在 Blender Y 轴镜像、传送带法线朝内或对象过度拆分，请使用 1.1.0 重新导出选区。

本次没有修改 Mod ID、Java 包名、命令、网络协议、导出魔杖数据结构、导出目录或一格对应一米的比例。

## 安装

1. 安装 Minecraft 1.21.1 与 NeoForge 21.1.244。
2. 移除客户端和服务端 `mods/` 目录中的旧 MineToMesh JAR。
3. 在客户端和服务端同时安装 `MineToMesh-1.1.0.jar`。

导出结果继续写入发起操作的玩家客户端：`.minecraft/minetomesh-exports/`。
