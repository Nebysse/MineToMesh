# MineToMesh 0.5.1

MineToMesh 0.5.1 completes the project's hard runtime identity migration while preserving the 0.5.0 export-wand workflow and Blender-ready glTF/OBJ output.

## Identity changes

- Mod ID: `minetomesh`
- Java root package: `com.nebysse.minetomesh`
- Production resource namespaces: `assets/minetomesh/` and `data/minetomesh/`
- Test fixture namespace: `minetomesh_test`
- Command root: `/minetomesh`
- Export root: `.minecraft/minetomesh-exports/`
- Artifact: `MineToMesh-0.5.1.jar`

## Breaking migration warning

This is a deliberate hard migration from the former `mcgltf` runtime identity.

- No NeoForge Missing Mapping is provided.
- No legacy resource namespace or network compatibility shell is provided.
- No `/mcgltf` command alias is provided.
- Existing wand data registered under the former Mod ID is not migrated.
- Back up worlds before opening them with 0.5.1.

The existing `.minecraft/mcgltf-exports/` directory is left untouched. New exports are written only to `.minecraft/minetomesh-exports/`.

## Installation

1. Install Minecraft 1.21.1 and NeoForge 21.1.244.
2. Remove older MineToMesh JARs from both client and server `mods/` directories.
3. Install `MineToMesh-0.5.1.jar` on both sides.

Actual scene files are written by the client that starts the export.

## Verification performed

The release candidate is gated by the complete unit-test suite, dedicated-server class-isolation test, NeoForge server smoke run, migration residue scan, production JAR content audit, metadata audit, and SHA-256 comparison of the uploaded GitHub asset.

Visual behavior in Minecraft and Blender remains an owner-run acceptance step because automated checks cover mechanical structure rather than aesthetic correctness.
