# MineToMesh 1.0.0

MineToMesh 1.0.0 is the first stable release of the NeoForge 1.21.1 world-to-Blender export pipeline.

## Highlights

- Corrected export coordinate handedness. glTF and OBJ no longer contain the intrinsic axis reflection that appeared as an X-axis mirror after Blender import.
- Restored source winding for triangles, quads, triangle fans, and triangle strips in both output formats.
- Preserved normals without reflection while retaining the existing origin and one-block-to-one-meter scale.
- Added the official MineToMesh cover to NeoForge's Mods screen.
- Retained the export wand workflow, connected-texture support, grass side overlays, Unicode names, player filtering, and client/server permission model.

## Coordinate contract

MineToMesh stores relative Minecraft coordinates without reflecting an axis. Blender's glTF importer performs the normal Y-up to Z-up rotation:

- Minecraft `+X` → Blender `+X`
- Minecraft `+Y` → Blender `+Z`
- Minecraft `+Z` → Blender `-Y`

Files exported with earlier builds retain their existing geometry. Re-export a selection with 1.0.0 to obtain the corrected orientation.

## Installation

1. Install Minecraft 1.21.1 and NeoForge 21.1.244.
2. Remove older MineToMesh JARs from both client and server `mods/` directories.
3. Install `MineToMesh-1.0.0.jar` on both sides.

The client that starts the export writes the glTF, BIN, OBJ, MTL, textures, materials, and report to `.minecraft/minetomesh-exports/`.

## Existing hard-migration boundary

The runtime identity remains `minetomesh` with Java package `com.nebysse.minetomesh` and command `/minetomesh`. No compatibility alias or Missing Mapping is provided for the former `mcgltf` identity. Back up worlds created with versions older than 0.5.1 before opening them.

## Verification

The release is gated by the complete unit-test suite, dedicated-server smoke test, coordinate and winding regression contracts, NeoForge metadata/logo checks, production JAR content audit, and SHA-256 comparison of the uploaded GitHub asset.
